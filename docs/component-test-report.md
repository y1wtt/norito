各ケースの検証内容:

- コード・WYSIWYG 両モードで全選択コピーの Markdown が元のソースと一致する。
- 切り取り、Undo、Redo、貼り付け、再コピーでデータが欠落しない。
- 明色・暗色 × 両モードでスタイルとビューを構築できる。これは画素比較や実画面の全ケース確認を意味しない。
- WYSIWYG の全 Unicode 文字境界の組み合わせでコピーが失敗せず、非空の選択が空のコピーにならない。
- アプリの貼り付け処理でソースを保持し、コンポーネント表示に戻り、Undo/Redo ができる。

追加の境界・異常系:

- 入れ子装飾の途中、日本語の一文字、改行をまたぐ選択、改行終端、文書途中の見出しをコピー。
- HTML の見出し、装飾、リスト、引用、チェックボックス、画像、リンク、表、コード、数式文字列、脚注の出力を検証。入力 HTML はエスケープする。
- ハイライト・上付き・下付きの HTML 出力、コード内とエスケープ済み記号を再解釈しないことを検証。
- クリップボード失敗、文書切り替え、revision 更新、選択変更、IME 入力中に遅延した切り取り結果が本文を削除しない。
- 編集キーの各割り当て、フォーカス外、Alt 併用、コンテキストメニューキーを検証。
- 既存の IME、改行、装飾のトグル、表編集、ページ遷移、ファイル DnD、保存と読み込み、描画クリッピングのテストも workspace 全体で実行。
- 表セルの装飾を描画用の書式付き文字列へ変換し、フォントを含むキャッシュキーで太字・斜体の取り違えを防ぐ。
- 外部 HTML の装飾・表・リスト・引用・コード・リンク・画像を Markdown に変換。Unicode、空白、コード内の空行、エスケープ、実行要素の除外を検証。
- コピーした相対パス画像とレンダリング済み Mermaid・数式の HTML 埋め込み、画像読み込み失敗・図のレンダリング失敗時の原文保持を検証。
- data URI 画像の復号、未保存文書でも使える読み込み経路、本文中画像の領域確保、エスケープ記号の表示と原文コピーを検証。

## 今回修正した不具合

1. 選択時に装飾記号を展開して選択範囲が変わり、全選択切り取り後に `****` が残る。
2. 下線形式の見出しや閉じ側 `#` がコピーから欠落する。
3. 数式の表示領域の一部を選択するとコピーが空になる。
4. ハイライト・上付き・下付きの HTML コピーが装飾を失う。
5. 表セルの太字・斜体などが通常の文字として描画される。
6. 外部 HTML の貼り付けがプレーンテキストに限定される。
7. HTML コピーで Mermaid・数式や相対パス画像を画像として渡せない。
8. 本文中の画像が前後の文字に重なる。
9. エスケープ記号のバックスラッシュが WYSIWYG に残る。

## 検証成果物

### 長文コピー時の HTML ヘッダー混入（2026-10-26 追記）

- 原因は clipboard-win 5.4.1 の HTML 位置情報生成。数値の再利用バッファに大きい値の桁が残り、長文では StartFragment が EndFragment を超える不正な CF_HTML を生成していた。従来の短い OS テストでは検出できなかった。
- 固定幅のヘッダーを各数値から生成する実装に置き換えた。UTF-8 バイト位置で計算し、末尾 NUL は EndHTML の範囲外とした。受信時も範囲・UTF-8 境界を安全に検証し、不正な HTML はプレーンテキストへフォールバックする。
- 全43コンポーネントとその結合文書、空文字、日本語・絵文字・結合文字・CRLF、10進桁数境界、長い data URI、逆転・範囲外・文字途中の位置情報を検証。書き手と読み手の往復一致だけでなく、実際のマーカー位置・バイト列を独立に比較した。
- workspace 通常テスト141件、clippy、releaseビルドが成功。Windows実クリップボードの明示テスト1件も成功し、長文のMarkdown・HTML・Unicodeテキストを確認した。実クリップボードテストは通常実行では除外する。
- 今回のGUIでの外部貼り付けは未実施。前述の操作ツールの画面不一致と承認拒否は解消していないため、OS形式の検証と区別する。
